# Smoothing results on the pilot clips (1-euro filter, experiment E2, first look)

Date of the run: 2026-11-21. These numbers are PROVISIONAL: one person (user u99), near distance,
plain background, bright light, 20 frames per second, camera picture 640 x 480.
Re-run on the training users before using any of this in the report.

Reproduce with:

    .venv\Scripts\python.exe evaluate_smoothing.py

The pilot clips are local files in data/landmarks/u99/ (not a real dataset). If they are deleted,
this file is the only record of the numbers.

Data used (clip counts per file):

u99/fist.json: 5 clips
u99/open_palm.json: 7 clips
u99/swipe_left.json: 6 clips
u99/swipe_right.json: 6 clips
u99/thumb_up.json: 6 clips

Chosen parameters, now the defaults in landmark_smoothing.py:
f_cmin = 0.5 Hz, beta = 0.02, d_cutoff = 1.0 Hz
  -> jitter -83.6 %, speed noise -68.2 %, added delay 26.9 ms, swipe amplitude kept at 0.971.
Neighbour with a little more margin: f_cmin = 1.0, beta = 0.02
  -> jitter -75.5 %, speed noise -64.2 %, delay 24.6 ms, amplitude 0.974.

Metric definitions are in the header of evaluate_smoothing.py. Reading hints:
- Unfiltered jitter is already tiny (0.0029 hand sizes, under one pixel at this distance) and the
  unfiltered speed noise (0.19 hand sizes per second) is small next to a swipe (about 4 hand
  sizes per second), so the gain is real but modest at this distance.
- The delay is the shift of the time centre of the palm-centre speed on swipe clips, an estimate,
  not the end-to-end latency (E9).
